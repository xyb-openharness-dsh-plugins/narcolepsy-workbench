# METRIC-GRADING · 本癌种启用哪几项分级、为什么

> 规则全文见 `docs/23-METRIC-GRADING-AND-ALERTS.md`；本文只回答"本仓启用哪些、为什么不全启用"。

## 结论先行

**本轮不启用 CTCAE 分级。** 界面不出现分级徽章，代码不引入 `ctcae.js`。

## 为什么

1. **本癌种没有对应的 CTCAE 条目**：CTCAE v5.0 是抗肿瘤治疗不良事件词表。发作性睡病不是肿瘤，其核心指标（发作次数、发作时长、ESS 总分、夜间觉醒次数）**都不是不良事件分级对象**。
2. **强行套用会误判**：用药耐受里的"腹泻次数"在 CTCAE 里确有分级，但那是抗肿瘤治疗的语境；把它套到替莫西芬/莫达非尼这类中枢兴奋剂上，会把"一天拉 4 次"显示成"2 级不良事件"，患者会误以为病情严重。**宁可没有徽章，也不给错标签。**
3. **量表不做分级**：ESS 总分 0–24 有公认分界（如 ≥11 提示日间嗜睡），但那是**筛查语境**，不是分级；一旦在界面写"重度嗜睡"，等于给出判读。本仓只显示分数与序列差值。

## 那什么情况下补

若后续接入**真实化验**（如药物相关的血常规/肝功能），按 `docs/23` §2.1 处理：

- 绝对阈值型（如中性粒细胞、血红蛋白）→ 可用成人通用下限近似，结果带 `approx: true`，界面写"按通用下限"；
- ×ULN 型（ALT/AST/ALP/总胆红素/肌酐）→ **必须用本次化验单自带 `ref_high`**，缺了返回 `needsUln` + 虚线徽章「需参考上限」。

**下限可以借，上限不能借。** 这条在 schema 里已预留 `ref_low`/`ref_high` 两列（见 `docs/SCHEMA.md` §3.7）。

## 三种"没有级别"的界面区分（补分级时才启用）

| 状态 | 徽章 | 说明 |
| --- | --- | --- |
| 正常 | 无徽章 | 有值且在范围内 |
| 缺参考上限 | 虚线「需参考上限」 | ×ULN 型缺 `ref_high` |
| 单位不符 | 虚线「单位待确认」 | 如 QTc 填 0.46 秒 |

本轮三者都不出现——因为没有分级。
