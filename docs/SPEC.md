# SPEC · 小睡宝 SnoozePal（发作性睡病）v0.1

状态：草案（G1 待签）。确认人/日期：**待签**。本文件不是已确认业务。

## 1. 问题与用户

- **用户**：发作性睡病患者（含青少年，由家长代记）；长期被误诊为"懒/抑郁/癫痫"后确诊者。
- **患者自己说的那句话**（非一手引语，0 访谈，推导句）：
  「我不是懒。我是真的在开会的时候突然就睡过去了，醒来还得装作在听。」
- **真实痛点（假设 H1–H5，见 USER-RESEARCH）**：①一天到底困几次、什么时段最凶说不清；②夜间觉醒/瘫痪/幻觉散落在记忆里；③ESS 量表每次重填，看不出变化；④管制药换药加量后效果与副作用记不住；⑤驾照、单位、学校要的材料临时凑。
- **不做**：诊断、分型判断（1 型/2 型）、用药建议、能否开车的结论、预后推断。

## 2. 最小闭环

输入（用户手记 / 导入检查原文）→ 落库（`xyb-narcolepsy.sqlite`）→ 回来看见（看板聚合 + 一图秀 + 量表序列）→ 出门（复诊问题清单 / 办事材料 / 本机导出）。

失败恢复：写入失败整体回滚并显示原因；服务不可用时业务区仍可读缓存快照（只读并标「离线快照」）。

## 3. 方案与取舍（ADR-1..4）

| # | 候选 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 睡眠日志按"每天一行"存 | **否** | 发作是离散事件，按天一行会把 3 次发作压成 1 个数字，趋势与时段聚合全失真 |
| 2 | 发作按事件存 + 时长作为数值指标 | **采纳** | 时段聚合、平均时长、单次最长时间三种问法都能答；与家族"指标"层复用 |
| 3 | ESS 8 题拆成 8 条指标 | **否** | 量表必须整次入档（同一时点 8 题同源），拆散会让"这次填了一半"变成合法数据 |
| 4 | ESS 整次一条记录 + 总分派生指标 | **采纳** | 总分进趋势，分项进整页视图（32 号）；总分由服务端算，前端不重算 |

## 5. 数据与 API

- 契约：`docs/SCHEMA.md` + `schema/0001_initial.sql`（M3 冻结，sha256 入 `freeze-contract.md`）。
- API：`GET /api/narcolepsy/bootstrap`、`GET /api/narcolepsy/health`、`GET/POST /api/narcolepsy/{naps,ess,night,meds,metrics,questions,notes}`。
- **无判定列**：不建 `diagnosis` / `risk_level` / `severity` 类列；`kind ∈ {numeric, grade, qual}` 只表达"这条指标怎么画"。
- 事实四层：`documents`（原文）→ `candidates`（候选）→ 记录/指标（核对后）不合并。

## 6. UI 与原型一致性

原型 `prototypes/v0.2/`（四件套，`file://` 直开）为唯一视觉基准；开发版 `public/` 逐字符对齐（`test/ui-parity.test.mjs`）。
顶栏三段式 + AI 五态；面板默认在右 35%（`lib/layout.js` 唯一来源）、可拖、可收起；窄宽（<760px）覆盖抽屉。
